# 常见问题

> 都是真会碰到的问题。每条先给**结论**，再给**怎么办**。
> 深入原理见 [01-design.md](01-design.md)，流程见 [03-workflow.md](03-workflow.md)。

---

# A. 装不起来 / 连不上

## 1. Zotero Local API 连不上，怎么办？

**结论：99% 是开关没开或没重启 Zotero。**

按顺序排查：

| # | 检查 | 怎么做 |
|---|---|---|
| 1 | Zotero 开着吗 | 本地 API 由 Zotero 进程提供，关掉 Zotero 就没了 |
| 2 | 开关开了吗 | Zotero → 设置 → Advanced → General → 勾选 **"Allow other applications on this computer to communicate with Zotero"** |
| 3 | **重启 Zotero 了吗** | 勾选后**必须重启**才生效。这一步最常被跳过 |
| 4 | 浏览器能打开吗 | 访问 `http://127.0.0.1:23119/api/users/0/items?limit=1`，能看到 JSON 就说明服务正常 |
| 5 | 换工具试 | `python tools/zotero/rvzotero.py ping` |

**退出码 3 = 连不上**，此时 `ping` 会直接打印可执行的修复指引，照做即可。

**Windows 特别提醒**：Zotero 本地 API 回的是 **HTTP/1.0**。Python 的 `urllib` 正常，但 PowerShell 的 `Invoke-RestMethod` 会以"基础连接已经关闭"失败——**那不是 Zotero 的问题**。用 `curl.exe` 或 `rvzotero.py`，不要用 `Invoke-RestMethod`。

详见 [05-zotero-access.md](05-zotero-access.md)。

## 2. 为什么不用现成的 Zotero 插件？

**结论：插件版本会静默给出错误读数，而且缺陷只在插件内部。**

这套工作流最初**就是用某个 Zotero 插件**跑的，然后撞上了两个缺陷：

- 列批注时**静默返回 0 条**（不报错）——最危险的那种失败；
- 批注在 **100 条**处**静默截断**（不报错、不给提示）。

它们在插件侧修过一次，但**插件升级会覆盖补丁**，需要反复重打。

所以仓库自带 `tools/zotero/rvzotero.py`：**一个纯标准库脚本，把这两个坑的规避逻辑写死在代码里**，与任何 Agent、任何插件版本无关。

> **你当然可以用你喜欢的插件。** 只要确认它对这三个行为正确处理：批注列全、超过 100 条会分页、会扫全部附件。做不到就调 `rvzotero.py`。

---

## 3. 能不能不用 Zotero？

**结论：能，但你会失去这套工作流最有价值的部分。**

工作流对 Zotero 的依赖只有三件事：

| 依赖 | 作用 | 替代方案 |
|---|---|---|
| 论文元数据（标题/作者/年/DOI） | 填 Paper Note frontmatter | 手填 |
| **原文** | 证据 `quote` 的来源 | 任何能定位到页码的 PDF 库 |
| **🟣 五色批注** | `research_position` 的唯一可靠信号源 | **没有等价替代** |

**关键在第三项。** 五色批注通道是"研究者只花高亮的力气、Agent 不用猜重点"的机制。换掉 Zotero，你得自己造一套"高亮 + 颜色 + 页码"的通道，而 Zotero 已经免费给你了（含官方页码标签）。

**折中做法**：文档层完全不绑定 Zotero——`03_Vocabulary/` 能独立用，导读和 Wiki 也能纯手工维护。你只是拿不到自动批注读取。

---

## 4. 能不用 Obsidian 吗？

**结论：能。Vault 就是一堆 Markdown 文件。**

Obsidian 提供三件便利，都不是必需的：

| 便利 | 不用 Obsidian 的话 |
|---|---|
| `[[双向链接]]` 可点击跳转 | 纯文本 `[[...]]` 仍然可读，只是不能点 |
| **Dataview** 仪表盘（自动汇总） | 仪表盘失效；用 `grep` / `rg` / 编辑器全局搜索代替 |
| 高亮 `==…==` 的视觉渲染 | 记号还在文件里，只是不显色 |

**注意**：`==高亮==` 与 `（Pass 2 补充）` 是**写进文件的真实字符**，不是 Obsidian 的私有格式——换任何编辑器都在。

如果你确实不用 Obsidian，可以删掉 `.obsidian/` 目录，其余一切照旧。**唯一必需的是 Dataview 插件**（只在用 Obsidian 时）——`index.md`、`_WikiIndex.md`、`Dataview_Dashboard.md` 的查询都依赖它。

---

## 5. Windows 上输出中文乱码怎么办？

**结论：这是终端编码问题，不是脚本问题。**

`rvzotero.py` 已经把 stdout 显式切到 UTF-8。如果仍然乱码：

```powershell
# 当前会话切成 UTF-8
chcp 65001
```

或用 Windows Terminal 代替老版控制台。**默认输出是 JSON**，需要人读时加 `--human`。

## 6. 全文取不到 / `retrieve` 没结果？

**结论：PDF 还没建全文索引。索引缺失时要如实报告，不要假装读过。**

Zotero 的全文索引不是自动的。修法：

- Zotero → 工具 → **Rebuild Fulltext Index**；或者
- 把那篇 PDF **打开一次**（Zotero 会顺手索引）。

**兜底的第二、三条路**（按优先级）：

1. `rvzotero.py retrieve --key <key> --query "<问题>"` —— 走 Zotero 全文索引，快，适合定向核验；
2. `rvzotero.py attachment --key <key>` 拿到 PDF 磁盘路径，再用你的文本提取工具读全文 —— 适合通读、公式密集或索引缺失；
3. `rvzotero.py get --key <key> --include notes` + 摘要 —— 适合快速判断值不值得细读。

**Agent 必须报缺口**：它应该说"索引里没找到这段"，不该说"这篇没讨论这个"。

# B. 批注相关

## 7. 为什么批注读出来是 0 条？

**结论：Zotero 的"列子对象"接口默认不返回批注。**

这是个**静默失败**——不报错、不警告，就是 0 条：

```text
GET /items/<key>/children                    → 只有附件和笔记，0 条批注
GET /items/<key>/children?itemType=annotation → 批注全在这里
```

**怎么办**：用 `rvzotero.py annotations --key <key>`——它已经强制带上过滤条件，并会**自动扫全部附件**。

如果你自己写代码或让 Agent 直接调 API，**必须显式带 `itemType=annotation`**。

---

## 8. 明明有 130 条批注，为什么只读出 100 条？

**结论：Zotero 在 100 条处静默截断。这不是你的错觉。**

Zotero 本地 API 对批注列表**硬性截断在 100 条**，且**不报错、不给提示**。只按返回结果作业会直接漏掉后面的批注。

**判断方法**：读响应头 `Total-Results` 拿真实总数，和实际条数对比。

**怎么办**：用 `rvzotero.py annotations --key <key>` —— 已内置 `start` 分页，**默认翻完全部**，自动突破截断。它还会把真实总数报给你（`matchedTotal` / `total`），方便核对。

**这是「默认即全量」**：不传 `--limit` 时输出全部命中——实测某父条目 130 条批注，返回就是 130 条，`truncated: false`。`--limit N` 只在你想快速预览时用；`--all` 现在是个把意图写明白的显式开关（无操作）。万一哪天看到 `truncated: true`，说明你显式传了上限，去掉 `--limit` 重跑即可。

> **经验规则**：Zotero 原生接口在 100 条处静默截断、不报错不提示——**这个坑由脚本内部解决，你不需要在调用侧做任何事**。但如果你绕过本脚本自己调 API，就必须用响应头 `Total-Results` 判总数、用 `start` 分页补齐。

---

## 9. 批注为什么只挂在某一个附件上？

**结论：正常现象。一篇论文常有好几个 PDF（原文 / 双语 / 译文），批注可能只落在其中一个上。**

实测遇到过：一篇论文两个 PDF 附件，130 条批注**全部**在双语版上，原始英文版 **0 条**。

**怎么办**：`rvzotero.py annotations --key <key>` 会**逐个附件**取再合并，你不用管。自己写代码的话，必须遍历全部 PDF 附件，不能只取第一个。

**附带一个坑**：如果批注挂在和你以为不同的附件上，**页码基准可能不一样**。用**章节标题类的批注**交叉验证分页——别默认两个附件页码一致。

---

## 10. 批注评论里的 `🔤…🔤` 是什么？

**结论：那是翻译插件的机器词典，**不是论文原文，也不是你写的话**。**

正确切分方式是**按区间**，不是按"整条含不含 `🔤`"：

| 位置 | 是什么 | 怎么处理 |
|---|---|---|
| `annotationText` | **论文原文** | 可作 `quote`，页码用官方页码标签 |
| 评论中 `🔤…🔤` **区间内** | 机器词典（翻译插件产物） | 只能填进 Vocabulary 的「机器词典」行，**永不作 `quote`** |
| 评论中区间**外**的非空文字 | **研究者本人写的话** | 如实记入 Paper Note §8.1，不得改写丢弃 |

典型形态就是「`🔤机器译文🔤` + 换行 + 你自己写的话」。

**两条铁律**：机器词典**永远不能**当论文原文引用；**也绝不能因为整条评论含 `🔤`，就把你写的话一并丢掉**。

---

## 11. 我明明是紫色高亮的重点，Agent 却写成了"你的观点"？

**结论：紫色是**标记**，不是**回答**。**

🟣 紫色说的是"**这段和我的研究相关**"。它是唯一 Agent 无法从文本推断的信号，所以用来判定 `research_position` / `research_relevance` 最可靠。

但它**不等于你说了什么**。所以紫色批注只能作 `R` 对象（研究者回应）的**候选**，必须经你确认才能写成正式回应。Agent 不得据此代你作答。

同理：任何你没回答的地方，正确状态是 `PENDING_RESEARCHER_RESPONSE`，而不是 Agent 猜一个答案填上。

# C. 体例与配置

## 12. 不想用中文体例怎么办？

**结论：体例是**默认配置**，不是硬编码。Architecture 与字段名本来就是英文。**

系统里语言分两层：

| 层 | 默认 | 能不能改 |
|---|---|---|
| **frontmatter 键与枚举值** | **英文** | ❌ **不要改**——Dataview 和 lint 靠它工作 |
| 说明性正文、分析、提问、Wiki 正文 | 中文 | ✅ 改成任何语言 |
| 论文摘录 | **保持原语言**，附中文翻译 | ✅ 可改成"保持原语言"或"附英译" |
| 数字 / 公式 / 模型名 / 指标名 | 不译 | ✅ 建议保持 |

改哪里：`00_System/Config.md` 的语言体例一节。**改完在文件里写明你的约定**，否则 Agent 下次会按默认走。

**唯一建议保持不变的是"摘录保持原语言 + 附翻译"**——如果你读英文论文却把摘录翻成中文，一年后核对原文时会对不上。

---

## 13. 集合名 / 目录名和我的不一样，要改吗？

**结论：要。模板里的是**示例**。**

`Config.md` 里的 Zotero 集合 → `research_position` 映射表（`00_Inbox` → 待判定、`10_AI核心` → `core`、`20_*` → `mentor`、`30_*` → `intersection`、`40_*` → `exploration`、`90_Archive` → `archived`）**只是默认值示例**。

**怎么改**：

1. 先用 `python tools/zotero/rvzotero.py collections` 看你自己有哪些集合；
2. 把 `Config.md` 里那张表改成你的集合名；
3. 注意规则：一篇论文可同时在多个子集合，但**顶层归属唯一**决定默认 position。

**目录名不建议改**：`01_Papers/`、`02_Wiki/`、`03_Vocabulary/`、`pass1/`、`pass2/`、`待精读/`、`已精读/` 和五个 Wiki 类型目录（`topic/` `concept/` `synthesis/` `gap/` `entity/`）都被仪表盘查询和 lint 直接引用。改名要同步改 `Dataview_Dashboard.md` 与规范文档。

---

## 14. `Research_Profile.md` 必须填吗？

**结论：必须。不填，紫批注就没有解释的依据。**

紫批注的意思是"这对我有用"——但"对我有用"取决于**你的研究坐标**。`Research_Profile.md` 就是这个坐标：

| 填什么 | 用来判定 |
|---|---|
| 主领域 | `core` |
| 导师 / 相邻领域 | `mentor` |
| 特别关注的交叉 | `intersection` |
| 探索政策 | `exploration` 会不会被误提升 |
| 研究偏好 | Agent 写笔记的详略与引用风格 |

**不填的后果**：Agent 会退回到猜。它可能把探索类论文标成核心，或者把边缘相关的标成核心——而这类错误会一路传到 Wiki 的主张表里。

---

## 15. 能改规范文档吗？

**结论：能。它们是你的文件。**

`00_System/` 下的规范复制到你 Vault 之后就是你的，随便改。但改之前想清楚：

| 规范 | 改了会怎样 |
|---|---|
| `AGENTS.md`（纪律） | Agent 行为立刻变。改前先确认你知道自己在放宽什么 |
| `*_Schema.md`（结构） | lint 和 Dataview 可能对不上，要同步改 |
| `Config.md`（环境） | 应该改——里面全是占位符 |
| `Workflow.md`（流程） | 影响 Agent 的执行顺序 |

**改完记得**：规范里写死了的东西（比如"行只增不删"），如果被 Agent 违反，先怀疑规范没读全，而不是规范没写。

# D. 用法与预期

## 16. 一篇论文要读多久？

**结论：分成两段计时，别混在一起算。**

| 阶段 | 谁做 | 典型耗时 |
|---|---|---|
| 生成导读 | Agent | 几分钟（取决于原文长度） |
| **读原文 + 五色批注** | **你** | **这篇的两三倍时间**（读一遍 + 回头补高亮） |

**关键预期**：导读是**5 分钟读完的一页**，它让你在**开始读之前**就知道值不值得读、重点在哪。所以它不能替代你读原文——**它只是让你的阅读时间花在对的地方**。

第一次用会慢一些（你要适应挑颜色的节奏）；写熟了之后，五色高亮基本是"顺手划"，不会额外增加多少负担。

**读到一半不想读了？** 直接停下就行。导读留在 `pass1/待精读/`，位置本身就是状态——它明确告诉你"这篇还没成稿"，不需要你去记。

---

## 17. 我刚 ingest 完，为什么 `pass2/` 里是空的？是不是漏做了？

**结论：这是**预期行为**，不是 bug。**

流程**故意**分两步：

```text
① Agent 出导读     →  01_Papers/pass1/待精读/<key>_<短标题>.md
② 你读原文 + 五色批注
③ 你说「批注好了」  →  才生成 01_Papers/pass2/<同名>.md
```

**为什么不能一步到位**：Paper Note 是**证据层**。它的证据基础是**你的批注 + Agent 的通读**。如果还没有批注就成稿，产出的就是一个**未经你确认、却长得像结论**的东西——而它后续会被当成事实源引用，还会喂给 Wiki。

所以：**缺批注就不成稿。** 宁可 `pass2/` 空着。

---

## 18. Agent 会不会瞎编？

**结论：架构上被三道防线限制，但那不等于"不会错"——所以每条主张都要能点回原文。**

| 防线 | 机制 |
|---|---|
| **三层证据纪律** | 原文（可引用）/ Agent 推断（必须标为暂定）/ 你的话（只有你能说）——三者不得混淆 |
| **主张必须带回链** | Wiki 每条主张的证据列强制 `[[Paper Note]]E编号 (页码)` 三件套，缺一即 lint 报警 |
| **两次点击可达原文** | 从 Wiki 命中 → Paper Note §4 证据行 → 原文摘录 + 位置 |

**它仍然可能**：摘录时漏掉限定条件、丢否定词、丢时间条件、把推测写成事实。所以还有一道**回原始核查**：逐段对照 `E` 证据对象，专查这四类腐化，**必须输出覆盖清单**（查了哪些页、哪些主张、每条的结论）——保证全量而非抽样。

**你的抓手**：任何一条看着不对的结论，顺着证据列点两下就能回到原文。点不到就是有问题的条目。

---

## 19. 我已经读过很多论文了，怎么迁移进来？

**结论：**不要批量补 ingest**。按"还在用得上"的顺序一篇篇来。**

不建议：一次性把整个库塞给 Agent 生成一堆 Paper Note——会产出一批**没有你批注的、长得像证据的东西**，直接污染证据层。

推荐做法，按优先级：

| 优先级 | 做法 |
|---|---|
| 1 | 挑**你正在引用、正在写**的那几篇，走完整两步流程（含五色批注） |
| 2 | 已经有批注的老论文：直接让 Agent 读批注 + 原文，**跳过第①步**，直接出 `pass2/` |
| 3 | 只在某个具体问题上需要的论文：**按需**补，别提前 ingest |
| 4 | 剩下的：留在 Zotero，用 `search` 随时查原文即可 |

**已有批注是最值钱的迁移资产**——它是你的判断，不是 Agent 的。先把带批注的迁进来。

**别忘了一件事**：迁移时 `log.md` 不用补历史记录，从今天开始记就行。

---

## 20. 为什么不用向量库 / RAG？

**结论：因为检索的目标不是"找相似段落"，而是"找到**有回链的结论**"。**

| 需求 | 向量库 | 这套方案 |
|---|---|---|
| 找到相关段落 | ✅ 擅长 | ❌ 不做（那是 Zotero 全文索引的活） |
| 知道一条结论**从哪来** | ❌ 不保证 | ✅ 证据列强制三件套 |
| 知道一条结论**被推翻过没有** | ❌ 无状态 | ✅ 状态机 + 变更记录 + `失效`/`替代` |
| 区分"论文说的"和"你判断的" | ❌ 天然混淆 | ✅ 三层证据纪律 |

加上一条工程理由：**不引入任何第三方依赖**，只要 Python 3.8+ 标准库就能跑——这样三年后它还能跑起来。

# E. 扩展与协作

## 21. 支持团队协作吗？

**结论：支持"各读各的"，不支持"多人同时写一个 Vault"。**

**能做的**：

- 整个 Vault 是纯 Markdown + Git 友好的，放 Git / 网盘 / 同步盘都行；
- 各人维护各自的 Vault，用同一套规范，笔记可互相引用；
- `97_…`/`log.md` 是**追加式**，天然适合多来源合并。

**要小心的地方**：

| 冲突源 | 为什么危险 |
|---|---|
| Wiki `§2` 主张表 | **行只增、状态只改**。两人同时改同一行容易覆盖，还可能违反"不删行"铁律 |
| `_WikiIndex.md` | 投影文件，会被增量重建，多人同时重建必然冲突 |
| `source_papers` / `[[链接]]` | 合并后可能指向同名的不同文件 |

**实践建议**：

1. 一个 Vault **只有一个"主张批准人"**——谁批准 Wiki 变更，只能有一个；
2. 要用 Git 就把 Wiki 变更**串行化**（别两人同时改 Wiki），论文笔记可以并行；
3. **别把别人的判断当成自己的**：`批准` 列写的是具体日期，`R` 对象的 `approved_for_wiki` 只由本人给出——协作者之间的信号不能混。

**如果你的团队要共享结论**：共享 Wiki 页 + Paper Note，各自保留自己的批注与 `research_position`。

---

## 22. 能一次 ingest 整个库吗？

**结论：技术上能，**别做**。**

第 17 条已经说了原因：`pass2/` 的证据基础是**你的批注**。批量 ingest 只能产出导读（那是可以的，但价值有限），或者产出没有批注的 Paper Note（那会污染证据层）。

**可以批量做的**：生成导读。它们是**阅读辅助**，不是事实源——一次性给 20 篇论文出导读，帮你判断先读哪篇，是合理的。

**不该批量做的**：跳过批注直接出 `pass2/`、直接写 Wiki。

---

## 23. Vault 需要备份 / 进版本控制吗？

**结论：需要，而且很容易。**

Vault 是纯文本 + 少量附件图标，`.gitignore` 已经排除 `.obsidian/` 里不该提交的东西。直接 `git init` 即可。

**三个提醒**：

1. **PDF 不进 Vault**——原文永远在 Zotero。这既避免了仓库膨胀，也保证了"原文不可变"。
2. **Wiki 的 `§6 变更记录` 是你的审计线索**——别在 commit 里把它删了。
3. **Obsidian 同步盘可能造成冲突副本**——如果开了同步，确认冲突解决规则，尤其是 Wiki 页。

---

## 24. 我能把 `03_Vocabulary/` 的内容用到别处吗？

**结论：能，但记住它是**语言层**，不能混进证据。**

Vocabulary 天然可以独立使用——它就是"我读文献遇到的不认识的词 + 它在每句话里的意思"。

**唯一的硬边界**：Vocabulary 的内容**不得出现在 Wiki 页、`E` 证据对象或主张登记表中**。

**为什么**：`E` 对象代表**论文说了什么**。一个词义不是论文的主张——把它塞进证据链，会让"证据"变得不可信。
