# 设计原理：为什么这套工作流要长成这样

> 读者：第一次接触本工作流的人。
> 读完本文你应该能回答三个问题：**它解决什么问题**、**三道防线分别防什么**、**为什么哪一道都不能省**。
> 想直接跑起来，去看 [02-quickstart.md](02-quickstart.md)；想知道每天怎么用，看 [03-workflow.md](03-workflow.md)。

## 结论先行

让 LLM 帮你读论文，最危险的不是它读不懂，而是**它读得太像懂了**——

它会顺手替你下结论，会把「我推断的」和「论文写的」混在一段话里，会在三个月后让你完全想不起某个判断是从哪来的。
而你自己在 Zotero 里划的那些高亮、写的那几句批注，读完就沉在 PDF 里，下一篇论文从零开始，知识不积累。

本工作流只做一件事：**给「人读文献」这件事装上证据纪律和记忆**。
它把 Agent 的角色从「替你读」压回「替你搬证据、替你记账」，把判断权完整地留给你。

三道防线，分别对应三种失败模式：

| 失败模式 | 具体表现 | 防线 | 落地机制 |
|---|---|---|---|
| **代你下结论** | Agent 的解读被当成你的判断写进知识库 | 防线一：三层证据纪律 | `Researcher Response` 只能由你提供；未答处留 `PENDING_RESEARCHER_RESPONSE` |
| **证据与推断混淆** | 分不清哪句是原文、哪句是模型脑补 | 防线二：五色批注通道 + 强制溯源 | 每个 `E` 对象必带 `quote` + `location`；机器词典永不作 `quote` |
| **知识不积累** | 读完就散，下次从零开始 | 防线三：两步 ingest + 主张账本 | 先导读 → 你批注 → 才成稿；Wiki 主张行只增、状态只改 |

## 一、问题：LLM 辅助精读的三种失败模式

### 1.1 代你下结论

你让 Agent 总结一篇论文，它给你一段流畅的中文。问题在于，那段中文里混着三种东西：

- 论文**说的**（可核查）；
- Agent **推的**（可能是对的，但它没标出来）；
- 你**想的**（其实你没说过，是 Agent 猜你想听什么）。

三样东西一旦混进同一段笔记，三个月后你自己也分不清哪句是你的判断。等你写论文要引这句话时，你只能整段重读原文。

**这不是模型不够聪明，是结构上缺了「谁说的」这个字段。**

### 1.2 证据与推断混淆

学术写作的硬要求是：每个论断都能追到**页码 / 章节 / 图 / 表 / 附录**。而对话式总结天然做不到这件事——它给你结论，不给你定位。

更隐蔽的一种混淆来自**翻译插件**。你在 Zotero 里看英文论文，翻译插件会把它的机翻结果写进批注评论里，形态通常是：

```text
🔤<机器译文>🔤
<你自己写的话>
```

如果 Agent 只判断「这条评论含不含 `🔤`」，就会把**你自己写的那句话一起丢掉**——而那句话往往是整篇论文里最值钱的信号。反过来，如果它把 `🔤…🔤` 里的机翻当成论文原文，知识库里就进了**谁也没说过的引文**。

**判据必须是「区间」，不是「整条含不含」。** 详见 [03-workflow.md](03-workflow.md) 的批注分流一节。

### 1.3 知识不积累

读第 1 篇论文时你建立了一套理解；读第 10 篇时，第 3 篇的结论你已经记不清了，于是重新推一遍。更糟的是：第 10 篇其实**推翻了**第 3 篇的结论，但你没有任何地方记录过这次推翻。

**光有笔记不叫积累，有「主张 + 证据 + 状态变迁」才叫积累。**

## 二、防线一：三层证据纪律

任何一句话，先问它属于哪一层。三层不得混淆：

| 层 | 是什么 | 判据 | 能不能当引文 |
|---|---|---|---|
| **Paper Evidence** | 论文原文 + 精确定位 | 有 `quote`（保持原语言）和 `location`（页 / 节 / 图 / 表 / 附录） | ✅ 可以 |
| **Agent Interpretation (Provisional)** | Agent 的推断 | 必须显式标注为**暂定** | ❌ 不可，需先经你确认 |
| **Researcher Response** | 只有你本人说的话 | 由你在笔记里写、或在对话中回答 | ✅ 作为你的判断，不是论文证据 |

还有**第四类，它不是证据**：

| 类别 | 判据 | 归属 |
|---|---|---|
| 机器词典 | 评论中 `🔤…🔤` **区间内**的文字 | `tool_generated`：既不是论文原文，也不是你的判断。**永远不能作 `quote`** |

### 未回答就留白，不许代答

Agent 需要你的解读时，只有一个合法动作：**提问**，然后把位置留成 `PENDING_RESEARCHER_RESPONSE`。

```
Agent Question：作者声称这个结论在低资源设定下成立。你认为这个结论可信吗？为什么？

PENDING_RESEARCHER_RESPONSE
```

它不得写一个叫「我的分析」的小节来填空，也不得因为你上次说过类似的话就替你补一句。**留白是特性，不是缺陷**——留白是数据，脑补是污染。

> 为什么这条要写死：一旦允许 Agent 代答，你的知识库里就会出现「看起来是你说的、其实不是」的判断。这类污染**无法事后清理**，因为你没有比对基准。

## 三、防线二：五色批注通道 —— 你只花划线的力气

### 3.1 核心洞察

那道真正的难题是：**Agent 怎么知道哪些地方重要？**

对话里问它「重点关注什么」，它只能猜。而你在读论文时，**手上已经有一套极其廉价且高保真的信号**——你的高亮。

所以本工作流不要求你写笔记、不要求你填表，**只要求你在 Zotero 里用五种颜色的高亮**：

| 颜色 | 代码 | 语义 | 去向 |
|---|---|---|---|
| 🟡 黄 | `#ffd400` | **生词** | `03_Vocabulary/`（语言层：不进证据、不进 Wiki） |
| 🟢 绿 | `#5fb236` | **定义术语或术语解释内容** | `E` 对象 → `concept` 页 |
| 🔵 蓝 | `#2ea8e5` | **影响、观点、解决方法** | `E` 对象 → 主张登记表（默认 `+` 支持） |
| 🔴 红 | `#ff6666` | **缺陷、现有问题、现有挑战** | `E` 对象 → `−` 反对证据、分歧、`gap/`（**`gap/` 页的主要来源**） |
| 🟣 紫 | `#a28ae5` | **与我的研究相关（可迁移 / 可借鉴）** | `research_position` / `research_relevance` 判定的**首要依据** |

你多花的时间是「换一种颜色」，Agent 得到的是一个**结构化的重点分布**：哪里是定义、哪里是主张、哪里是缺陷、哪里和你有关。

### 3.2 为什么是这五色

绿、蓝、红是**论文内容的三类基本零件**：定义（它是什么）、主张（它说什么）、缺陷（它缺什么）。分开它们，是因为它们流向三个不同的地方——定义进概念页，主张进主张登记表，缺陷进空白页。

黄是**语言层**，单独抽出来是因为：生词与知识无关。它不该出现在你的知识库里，但它需要被单独复现（同一个词在不同论文里的语境义常常不同）。

紫是**唯一 Agent 无法从文本推断的信号**。「这段和我的研究有关」——这句话只存在于你脑子里。绿蓝红都能从内容猜个八九不离十，**紫不能**。所以紫是 `research_position` 与 `research_relevance` 判定的首要依据。

### 3.3 紫是标记，不是回答

这是个容易搞混的边界：紫色高亮表示「这段对我重要」，但它**没有说为什么重要、也没说你怎么看**。

所以紫只能作为 `R` 对象的**候选**，**不得自动写成 Researcher Response**。这一点与防线一完全一致。

## 四、防线三：两步 ingest —— 先导读，批注之后才成稿

### 4.1 机制

引入一篇新论文时，**不要一次生成两份文件**。分两步：

**第一步 · 导读**（Agent 自动完成）

产出 `01_Papers/pass1/待精读/<zotero_key>_<短标题>.md`，一份**5 分钟读完的一页**，七段固定结构：

顶部（页码基准 + 一句话）→ 一、要解决的问题 → 二、**论文架构地图** → 三、**核心观点** → 四、读前必备的概念与记号 → 五、阅读路线 → 六、带着这几个问题读。

硬约束：
- 全文 ≈ 1000 字，**1200–1300 中文字为硬上限**（宁短不长）；
- **不写实验结果、不写数字、不写作者对结果的解释与最终结论**——「核心观点」只记录作者**声称**什么，不记录作者**证明了**什么；
- **不得出现** `E` 编号、主张、Wiki 提案、`R` 对象、`PENDING_RESEARCHER_RESPONSE`。

**第二步 · 你读原文 + 做五色批注**（人的时间，不可省）

**第三步 · 成稿**（Agent 在你确认后完成）

产出 `01_Papers/pass2/<同名>.md`（13 节，**证据层**），同时把导读移入 `01_Papers/pass1/已精读/`。

### 4.2 位置即状态

导读不写状态字段。**它待在哪个文件夹，就是什么状态**：

| 目录 | 含义 | 判据 |
|---|---|---|
| `01_Papers/pass1/待精读/` | 还没成稿 | 尚无 `pass2/<同名>.md` |
| `01_Papers/pass1/已精读/` | 已成稿 | 已生成 `pass2/<同名>.md` |

两份文件**按文件名配对**（basename 相同），靠文件名对应，**不引入索引文件、不加关联字段**。状态只在一处表达——这是「不双写」原则的第一次应用（后面在主张登记表里还会见到）。

### 4.3 为什么缺批注就不该成稿

这是整套设计里最关键、也最容易被当成「多此一举」的一条。理由有三：

1. **`pass2/` 是证据层，而它的证据基础是「你的批注 + Agent 通读」**。缺了批注，它就只剩 Agent 通读——那它会产出**一个未经你确认、却长得像结论的东西**。这类文件比没有文件危险得多：它会被后面的每一步当作事实源引用。

2. **批注优先于 Agent 的通读结论**。你标过的位置就是重点。先成稿、后补批注，等于让 Agent 的权重压过你的，然后你再花力气去改它——顺序反了，成本更高。

3. **这是 Wiki 污染的上游阀门**。`pass2/` 的 §11 是 Wiki 变更提案的唯一入口。如果 `pass2/` 是在没有你的输入时生成的，那么提案也是。**在源头拦住，比在下游清理便宜。**

### 4.4 `pass1` 绝不双写

导读里一旦出现 `E` 编号、主张、Wiki 提案、`R` 对象或 `PENDING_RESEARCHER_RESPONSE`，你就有了**第二个证据源**——此后每次引用都要想「以哪份为准」。

所以分工是硬的：**导读只写「读之前你需要知道什么」，总结只写「读完之后我们确认了什么」**。互不复制。

### 4.5 成稿之后还要标两种记号

| 要标什么 | 怎么标 | 一句话含义 |
|---|---|---|
| 某段判断来自你的批注 | 用 Obsidian 高亮 `==…==` 包住 | 「**这段来自批注**」 |
| 后续轮次补进去的位置 | 行末加 `（Pass 2 补充）` | 「**这一处是后来补的**」 |

`==高亮==` 只用于批注带出的内容，**不要拿它做强调装饰**——否则这个记号就失效了。

## 五、第四层：主张账本 —— 让知识可进化

三层证据纪律保证了「单篇论文读得干净」，但**跨论文的知识**还需要一个会进化的结构。这就是 `02_Wiki/`。

### 5.1 不是摘要堆，是主张账本

Wiki 页不是「论文摘要合集」，而是**一组带稳定 ID 的主张，每条主张挂着它的证据**。

核心是每页的 **§2 主张登记表**（唯一事实源），8 列：

| ID | 主张 | 证据 | 状态 | 批准 | 生效 | 失效 | 替代 |
|---|---|---|---|---|---|---|---|
| `C01` | 示例主张 | `+[[PaperA]]E03 (p.5)` · `−[[PaperC]]E07 (p.9)` | `contested` | — | 2026-01-01 | — | — |

证据列强制三件套：`[[Paper Note]]E编号 (页码)`。
- `[[…]]` 可点击 → 从 Wiki 命中**直接跳回** `pass2/` 笔记；
- `E编号` → 指到笔记 §4 的具体证据行；
- `(页码)` → 让你不必在笔记里翻找。

**没有回链的主张视为无依据**，lint 会报警。这条硬要求的效果是：从 Wiki 层检索到的任何结论，都能在**两次点击内**到达论文原文位置。

### 5.2 可进化的三个必要条件

| 条件 | 为什么必须 |
|---|---|
| **主张有稳定 ID**（`C01, C02, …`，页内唯一、永不复用） | 否则无法追踪同一条主张的演变 |
| **行只增、状态只改，行永不删除** | 否则看不到「共识如何被推翻」——被推翻的行标 `refuted` 并保留 |
| **每次 ingest 必做主张影响检查** | 否则新证据进不来，Wiki 会僵化成论文摘要墙 |

### 5.3 状态机：只改状态，不删行

```text
proposed ──第 2 篇独立论文给出 + 证据──► supported ──研究者批准──► consensus
    │                                        │                      │
    │                                        │  出现 − 证据          │
    └────────────────────────────────────────┴──────────────────────┘
                                             ▼
                                         contested ──研究者裁定 / − 被限定为 ~──► consensus
    任意状态 ──被明确推翻──► refuted
```

两条容易忽略的规则：

- **独立性有定义**：不同研究组、或在不同数据集上的独立验证。**同一篇论文的多个实验不算独立。**
- **状态 ≠ 是否现行**。状态说的是**证据强度**，`失效` 说的是**是否仍是当前答案**。一条 `supported` 的主张完全可能因为被更精确的主张取代而失效——此时填 `失效` + `替代`，**状态保持不变**。

**双向流转同样重要**：`consensus → contested` 不是事故，是本框架正常工作的表现。只要变更记录在案。

### 5.4 能遗忘

知识库最大的敌人不是错误，是**过时的正确**。

Wiki 页的 frontmatter 带 `effective_from` / `retired_at` / `superseded_by`；主张行带 `生效` / `失效` / `替代` 列。

**`retired_at` 非空、或主张 `失效` 非空 → 检索期默认过滤。** 只有你显式问「这条为什么变了 / 历史是什么」时才纳入，并在回答里标注「**此条已废止**」。

遗忘不是删除：内容保留供回溯，只是**默认不再拿它回答新问题**。

### 5.5 目录即类型

Wiki 有五个目录，**页面放在哪个目录就是哪一类，frontmatter 不写 `type`**：

| 目录 | 回答的问题 | 核心产物 |
|---|---|---|
| `topic/` | 「这个方向由哪些问题构成？」 | 方向地图（本身不写主张） |
| `concept/` | 「X 是什么？」 | working definition |
| `synthesis/` | 「关于 X，文献整体说了什么？」 | 带边界的当前最佳理解 |
| `gap/` | 「什么还不知道、值得做？」 | 可研究问题 + 验证路径 |
| `entity/` | 「这个具体的人 / 组 / 系统 / 模型 / 数据集是谁？」 | 实体档案 |

三条后果：① **frontmatter 不写 `type`**——移动文件就是改类型，不存在第二份真相；② 查询用 `file.folder`；③ 任何内容页都必须落在五个目录之一。

### 5.6 三条更新纪律

1. **最小 diff**：只改受影响的**具体行**，不重写整页。**禁止把新素材追加到页尾**——那会让知识页退化成时间线。
2. **唯一例外**：§1「综合与当前理解」随每次实质更新**整段重写**，因为它是本页最接近结论的部分。
3. **验收指标不写进各页 frontmatter**（那是双写）——集中在 `_WikiIndex.md` 的验收区，由检查生成。

## 六、全流程图

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Zotero（不可变源 · 只读）                                                 │
│  PDF 原文  ·  书目元数据  ·  你的五色批注                                 │
└───────────────────────────┬──────────────────────────────────────────────┘
                            │  Agent 只读访问
                            │  （本仓库统一走 tools/zotero/rvzotero.py）
                            ▼
            ┌───────────────────────────────┐
            │ ① ingest · 第一步：只出导读    │   Agent 通读全文
            │    七段 · ≈1000 字 · 5 分钟    │   不写结论 / 不写数字
            └───────────────┬───────────────┘
                            ▼
   01_Papers/pass1/待精读/<zotero_key>_<短标题>.md
                            │
                            │  ★ 你在这里花时间：带导读读原文
                            │     在 Zotero 里做五色批注
                            │     （这一步没有任何 Agent 能替你做）
                            │
                            │  你说：「批注好了」
                            ▼
            ┌───────────────────────────────┐
            │ ② ingest · 第二步：成稿        │   先读批注 → 再读原文
            │    批注沉淀 → §8               │   批注优先于 Agent 通读
            └───────────────┬───────────────┘
                            │
              ┌─────────────┴──────────────┐
              ▼                            ▼
 01_Papers/pass2/<同名>.md      01_Papers/pass1/已精读/<同名>.md
 （证据层 · E 对象 · 13 节）      （导读移动 = 状态变更，不写状态字段）
              │
              │  §11 主张级变更表（提案）
              │  ↓  ⛔ 人工确认点：你批准
              ▼
 02_Wiki/<topic|concept|synthesis|gap|entity>/<页>.md
 （主张层 · §2 主张登记表 = 唯一事实源 · 行只增、状态只改）
              │
              ▼
            ┌───────────────────────────────┐
            │ ③ query：Wiki → pass2 → Zotero │
            │    四分类回答                   │
            └───────────────────────────────┘
```

三层目录，按**层**划分而不是按状态：

```text
<VAULT>/
├─ 01_Papers/pass2/   证据层 —— 论文说了什么（可核查）
├─ 02_Wiki/           主张层 —— 文献整体说明了什么（可进化）
└─ 03_Vocabulary/     语言层 —— 我还不认识哪些词（与知识无关）
```

`01_Papers/pass1/` **不是第四个事实源**，它只承载阅读辅助。

## 七、日常循环

```text
     ┌──────────────────────────────────────────────────────┐
     │                                                      │
     ▼                                                      │
  ingest（只出导读）→ 你读原文 + 五色批注 → 说「批注好了」    │
                                    │                       │
                                    ▼                       │
                            pass2 成稿 + §11 提案           │
                                    │                       │
                                    ▼                       │
                          ⛔ 你批准 → 写入 02_Wiki/          │
                                    │                       │
                                    ▼                       │
                              lint（体检六组）──────────────┘
                                    │
                                    ▼
                    query（问答）：Wiki → pass2 → 原文
```

每**第 5 篇** ingest 后，Agent 应**主动建议**跑一次合并检查（去重合并 / 回原始核查 / 冲突场景限定 / 失效下线）——**只建议，不自行执行**。

---

## 八、设计边界：这套东西不做什么

明确不做的事，和明确做的事一样重要：

- **不替你读论文。** 导读的目的是让你 5 分钟判断「值不值得读、重点在哪」，不是让你不用读。
- **不替你下判断。** 未回答就留 `PENDING_RESEARCHER_RESPONSE`。
- **不把 PDF 存进 Vault。** Zotero 是不可变源；Vault 里只有笔记。
- **不自动提升你的判断为持久结论。** Wiki 变更需你批准。
- **不自动执行合并检查。** 只建议。
- **不依赖某个特定 Agent 实现。** 见 [06-agent-integration.md](06-agent-integration.md)：任何能**读文件、写文件、跑 shell** 的 Agent 都能接入。
- **不引入第三方依赖。** Zotero 访问层只用 Python 3.8+ 标准库。
