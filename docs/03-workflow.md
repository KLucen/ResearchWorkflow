# 工作流：ingest / query / lint 三阶段全流程

> 本文是**人读版**，展开每个阶段「输入什么、Agent 做什么、产出什么、哪里需要你点头」。
> **权威规范在 Vault 内**：`00_System/Workflow.md`（阶段展开）、`00_System/AGENTS.md`（纪律）。本文与它们冲突时，以 Vault 内的为准。
> 设计理由见 [01-design.md](01-design.md)；字段细节见 [04-schemas.md](04-schemas.md)。

## 结论先行

| 阶段 | 一句话 | 产出物 | 你的介入 |
|---|---|---|---|
| **ingest** | 引入新论文。**分两步**：先只出导读，你批注之后才成稿 | `pass1/待精读/*.md` → `pass2/*.md` | **必须**：读原文 + 五色批注 |
| **query** | 回答研究问题。Wiki → `pass2/` → Zotero 原文，逐层下钻 | 四分类回答 | 可选：追问与裁定 |
| **lint** | 体检。六组检查，找出结构 / 证据 / 溯源 / 知识 / 主张 / 研究问题 | `00_System/lint-report.md` | 看报告、决定修哪些 |

跨阶段的一件事：**Wiki 变更必须经你批准**。Agent 只能提案。

# 阶段一 · ingest

## 1.0 两步的时序

```text
第一步（Agent）        第二步（你）              第三步（Agent）
出导读        ──►    读原文 + 五色批注   ──►   成稿 pass2 + 提案
pass1/待精读/         在 Zotero 里做             pass2/ + 导读移入 已精读/
```

**缺第二步就不做第三步。** 这是硬规则，理由见 [01-design.md](01-design.md) §4.3。

---

## 1.1 第一步：生成导读

**输入**：Zotero 条目（item key / URI / 标题）。

**Agent 动作**：

| # | 动作 | 说明 |
|---|---|---|
| 1 | **检索定位** | 通过 `tools/zotero/rvzotero.py search` 找到条目 |
| 2 | **取元数据与笔记** | `rvzotero.py get`（含 `notes` / `attachments`） |
| 3 | **取批注**（若有） | 逐个附件取，见 [05-zotero-access.md](05-zotero-access.md)。首次 ingest 通常还没有批注 |
| 4 | **读原文** | 优先用 Zotero 全文索引做定向核验；需通读时取 PDF 路径 → 提取全文 |
| 5 | **理清章节与页码** | 只到「章」这一层，**不逐小节**；确定页码基准是哪个附件 |
| 6 | **写导读** | 七段固定结构，见下 |
| 7 | **追加日志** | `log.md` 加一行 |

**产出物**：`01_Papers/pass1/待精读/<zotero_key>_<短标题>.md`

七段固定结构：

| # | 段 | 写什么 | 约束 |
|---|---|---|---|
| 顶部 | 页码基准 + 一句话 | 声明页码指哪个附件；一句话说明这篇在做什么 | 一句话 ≤ 40 字，**不评价** |
| 一 | 要解决的问题 | Problem / Gap / Motivation | ≤ 150 字；**不写它做成了没有** |
| 二 | **论文架构地图** | 表格 `章 \| 页 \| 在做什么 \| ★ \| 建议`，一行一章 | ★ 按「与你的研究相关、可复用」评，**不按作者篇幅权重** |
| 三 | **核心观点** | 作者**明确声称**的贡献与主张，3–5 条 | 每条标章节定位 |
| 四 | 读前必备的概念与记号 | 表格 `概念／记号 \| 一句话`，3–5 条 | 只给「是什么」 |
| 五 | 阅读路线 | 表格 `目的 \| 读法 \| 约需` | 时长按「边读边想」估算 |
| 六 | 带着这几个问题读 | 3–5 问，每问附**一行定位** | 判断类问题标「**论文不答**」 |

**篇幅**：全文 ≈ 1000 字，**1200–1300 中文字为硬上限**。宁短不长。

**「答案在」的写法**：优先让你自己从原文找答案——只给**一行定位**（在哪、怎么判），**不给完整论证**。判断类问题（没有客观答案的）必须标「**论文不答**」，那只有你能回答。

**硬约束（出现任意一项即违规）**：`E` 证据对象、主张、Wiki 提案、`R` 对象、`PENDING_RESEARCHER_RESPONSE`。

**人工确认点**：无强制确认，但请花 1 分钟扫一眼验收清单（见 [02-quickstart.md](02-quickstart.md) §7.3）。导读生成后**不再改动**——它是「读之前」的辅助。

---

## 1.2 第二步：你读原文 + 五色批注

**这一步没有任何 Agent 能替你做。** 它是整条流水线的信号源。

在 Zotero 里用五种颜色高亮：

| 颜色 | 代码 | 语义 | 你的操作 |
|---|---|---|---|
| 🟡 黄 | `#ffd400` | **生词** | 遇到不认识的词就划 |
| 🟢 绿 | `#5fb236` | **定义术语或术语解释内容** | 「这里在定义什么」 |
| 🔵 蓝 | `#2ea8e5` | **影响、观点、解决方法** | 「作者主张什么、提出怎么解」 |
| 🔴 红 | `#ff6666` | **缺陷、现有问题、现有挑战** | 「哪里有问题、还缺什么」 |
| 🟣 紫 | `#a28ae5` | **与我的研究相关（可迁移 / 可借鉴）** | 「这段对我有用」 |

几条经验：

- **红与蓝的边界**：🔵 是「作者提出/主张了什么」（含解决方法），🔴 是「哪里有问题、还缺什么」。🔴 不限于本文自身的局限，也包含领域层面的现有问题与挑战——**因此它是 `gap/` 页的主要来源**。
- **紫色最省事也最值钱。** 它是唯一 Agent 无法从文本推断的信号（绿蓝红都能推），所以它是 `research_position` / `research_relevance` 判定的**首要依据**。但它只是**标记**不是**回答**——Agent 不得据此代你作答。
- **可以在评论里写字。** 你的评论会被如实记入 `pass2/` 的「研究者评论」列（但仍需你确认才能升格为 `R` 对象）。

读完，对 Agent 说：**「批注好了」**（或「读完了」）。

---

## 1.3 第三步：成稿（生成 `pass2/`）

**触发**：你说「批注好了 / 读完了」。

**输入**：你的五色批注 + Agent 此前的通读。

**Agent 动作**：

| # | 动作 | 关键要求 |
|---|---|---|
| 1 | **先读批注，再读原文** | 按五色分流（见下表）。**批注优先于 Agent 自己的通读结论**——你标过的位置就是重点 |
| 2 | **批注沉淀进 §8** | 每条批注转成 `E` 对象，标 `source: annotation:绿\|蓝\|红\|紫`，页码用 Zotero 官方页码标签 |
| 3 | **写 §1–§7** | 以 Agent 通读为底；**受批注影响的段落用 `==高亮==` 包住** |
| 4 | **提问** | 一次最多 1–3 个高价值问题；未答处留 `PENDING_RESEARCHER_RESPONSE` |
| 5 | **Agent 补充** | 批注很少时自行补重点，但**必须写进 §8.3「Agent 补充」**，不得混入你的信号 |
| 6 | **主张影响检查** | 填 **§11 主张级变更表**，等批准 |
| 7 | **改状态与位置** | `reading_status: deep-read`；**导读移入 `pass1/已精读/`**；`log.md` 加一行 |

**五色分流口径**（执行标准）：

| 颜色 | 处理 |
|---|---|
| 🟡 | 写入 `03_Vocabulary/`（按词元归并；`acquired: true` 的跳过）。**不进证据、不进 Wiki** |
| 🟢 | → `E` 对象 → `concept` 页提案 |
| 🔵 | → `E` 对象 → 主张登记表（默认 `+` 支持） |
| 🔴 | → `E` 对象 → `−` 反对证据、分歧、`gap/` 线索 |
| 🟣 | → §7 研究关系；`research_position` / `research_relevance` 的**首要依据**；仅作 `R` 候选，**不得代答** |

**产出物**：

```text
01_Papers/pass2/<zotero_key>_<短标题>.md     ← 证据层，13 节
01_Papers/pass1/已精读/<同名>.md              ← 导读移动过来
03_Vocabulary/<lemma>.md                     ← 🟡 生词（有则建/追加）
```

两份文件**同名配对**，靠文件名对应。

**人工确认点**：§11 的主张级变更表需要你批准，才会写入 `02_Wiki/`。

### 批注读取的两个坑（Agent 必须处理）

1. **评论归属按 `🔤…🔤` 区间切分，不是按「整条含不含 `🔤`」。**

   ```text
   🔤<机器译文>🔤          ← 区间内：机器词典，tool_generated
   <你自己写的话>           ← 区间外：研究者本人的话，如实记录
   ```

   机器词典**永远不能作 `quote`**；也**不得因为整条评论含 `🔤` 就把你的话一并丢掉**。典型形态就是「机翻 + 换行 + 你写的话」。

2. **批注可能只挂在某一个附件上，且可能在 100 条处静默截断。** 一篇论文常有好几个 PDF 附件（原文 / 双语 / 译文），必须**逐个附件**取；条数接近或等于 100 时必须分页补齐。详见 [05-zotero-access.md](05-zotero-access.md)。

---

## 1.4 后续增补循环

你继续批注、或在对话里回答了问题之后，Agent **就地修订** `pass2/` 受影响的位置：

| 记号 | 含义 |
|---|---|
| `==高亮==` | **这段来自批注**（首次生成时就要标） |
| 行末 `（Pass 2 补充）` | **这一处是后来补进去的** |

两个记号可以同时出现。**`==高亮==` 只用于批注带出的内容**，不要拿它做强调装饰。

# 阶段二 · query

**输入**：一个研究问题。

## 2.1 下钻顺序（硬性）

```text
提问
 └→ 02_Wiki/           先查主张层（已有跨论文结论）
     └→ 01_Papers/pass2/   回溯证据：证据只在 pass2
         └→ Zotero 原文      仅当证据细节缺失时才下钻
```

**`pass1/` 是导读，不是引用来源。** 它只是阅读辅助。

## 2.2 检索链与命中依据

```text
_WikiIndex        定位主题
 └→ topic/        方向地图
     └→ concept/ + synthesis/ + gap/     §2 主张行
         └→ 证据列 `[[Paper]]E03 (p.5)`   ← 可点击
             └→ pass2/ 笔记 §4 证据表      原文摘录 + 译文 + 精确位置
```

**硬要求**：从 Wiki 命中的任何结论，都必须能在**两次点击内**到达论文原文位置。这就是证据列强制 `[[Paper Note]]E编号 (页码)` 三件套的意义。

## 2.3 回答必须四分类

| 类别 | 含义 |
|---|---|
| **established** | 已确立的证据 |
| **conflicting** | 彼此冲突的证据 |
| **researcher-approved** | 你已批准的解读 |
| **unresolved** | 未解决的疑点 |

**召回期默认过滤**：`retired_at` 非空的页面、`失效` 非空的主张，默认不纳入回答。只有你显式问「这条为什么变了 / 历史是什么」时才纳入，并标注「**此条已废止**（失效于 YYYY-MM-DD，由 `Cxx` 取代）」。

## 2.4 人工确认点

- 回答里出现「不确定 / 冲突」时，你可以裁定——**裁定结果要落回 Wiki 才算数**（走 §11 提案 → 你批准）。
- Agent 不得把「查不到」说成「没有」。缺失的证据要如实报告为缺口。

# 阶段三 · lint

**产出物**：`00_System/lint-report.md`（**覆盖写**），并在对话里给摘要与修复建议。

## 3.1 六组检查

| 组 | 查什么 |
|---|---|
| **结构** | YAML 非法或缺失、断链、必填字段缺失、**导读位置与 `pass2/` 是否一致**、`pass1/` 是否双写、**导读体量 ≤ ~1300 中文字**、Wiki 目录即类型（内容页必须在五个目录之一、frontmatter 不得有 `type`）、Wiki 证据回链三件套、**页尾追加痕迹**、Vocabulary 轻量检查 |
| **证据** | 论断没有引用、引语没有位置、没有证据支撑的综合 |
| **溯源** | 未经批准的研究者判断被写入、Agent 解读被误标成研究者判断 |
| **知识** | 重复的 Wiki 概念、陈旧页面、未记录的矛盾、该更新却没更新的页面 |
| **主张一致性** | 标 `consensus` 但独立来源 < 2 篇、标 `contested` 却无 `−` 证据、`E` 编号悬空、同一主张多页重复登记、§2 表出现整行删除痕迹 |
| **研究** | 反复出现的未决问题、证据缺口、跨论文新兴主题、可能的研究空白 |

**结构组的三条关键判据**（最容易踩）：

1. **导读位置与 `pass2/` 必须一致**：`待精读/` ⇒ 尚无 `pass2/<同名>.md`；有 `pass2/<同名>.md` ⇒ 导读应在 `已精读/`。导读落在 `pass1/` 根下即违规（根下只放模板）。
2. **`pass1/` 不得双写**：出现 `E` 编号、主张、Wiki 提案、`R` 对象、`PENDING_RESEARCHER_RESPONSE` 即违规。
3. **页尾追加痕迹**：新内容以「补充：…」形式堆在页尾 = 违反最小 diff 纪律。

## 3.2 定期检查（四类）与覆盖清单

| 检查 | 做法 |
|---|---|
| **去重合并** | 按 `topics` 聚类 → 找语义重复 / 已被取代 / 过度碎片化的条目 → 归并或重写；**归并时旧页标 `retired_at` + `superseded_by`，不删** |
| **回原始核查** | **逐段**对照 `pass2/` 的 `E` 证据对象，专查四类腐化：**漏了关键限定 / 丢了否定词 / 丢了时间条件 / 把推测当事实** |
| **冲突场景限定** | 矛盾的两条若各自成立，在 §4 写明适用条件（时间 / 对象 / 地域 / 任务）；证据不足则保留待确认，**不强行裁定** |
| **失效下线** | 给内容加 `effective_from` / `retired_at`；检索期过滤 |

**覆盖清单（coverage manifest）是硬要求**：大批量核查**必须**输出「检查了哪些页、哪些主张、每条的结论」，写入 `00_System/lint-report.md`——**保证全量而非抽样**。没有覆盖清单的核查不算完成。

**触发**：内容量增长到**每第 5 篇 ingest** 时，Agent 应**主动建议**跑一次合并检查。

**人工确认点**：**只建议，不自行执行**——等你点头。

# 跨阶段 · Wiki 变更闸门

Wiki 的所有实质变更都走同一个闸门：

```text
pass2/ 生成 → §11 主张级变更表（提案）
                    │
                    │  动作 / 页面 / Claim ID / 变更 / 依据 E 编号
                    ▼
            ⛔ 你批准（approved_for_wiki: true 由你本人给出）
                    │
                    ▼
            写入 02_Wiki/ → reading_status: completed
```

**每次 ingest 都必须回答一个问题**：本次读到的 `E` 证据，**是否触及 `02_Wiki/` 中已有的某条主张**？

- 触及 → 提**状态流转**；
- 不触及 → 只提**新增主张**或**新建页面**。

**没有对应 `E` 编号支撑的提案不要提。**

变更类型只有这几种：`新增主张` / `状态流转` / `新增分歧` / `分歧消解` / `共识达成` / `升级为 gap` / `页面创建` / `页面退役`。

## 三条铁律

1. **行永不删除**——推翻是正常的知识进化，不是要抹掉的错误。被推翻的行标 `refuted` 并保留。
2. **状态不能跳级**——只能按状态流转表变更。
3. **ID 页内唯一、永不复用**。

## 更新顺序（最小 diff）

```text
① 先跑检查（frontmatter 合法 / 链接可达 / 证据链完整 / 无失效引用）
② 定位受影响的「具体行」——不是整页
③ 增删改对应段落，同步维护链接 / topics / updated / 证据引用 / §6 变更记录
④ 增量重建 _WikiIndex 的受影响区，不整页重写
```

> **禁止把新素材粗暴追加到页尾。** 这会让知识页退化成时间线。唯一允许整段重写的地方是 §1「综合与当前理解」。

## gap 升级条件

未解决问题满足**任一**条件，Agent 应**建议**升级为独立 `gap/` 页（**需你批准，不得自行创建**）：

1. 在 **≥2 个** Wiki 页中重复出现；
2. 有明确的**缺失证据类型**；
3. 你判断其重要。

升级时在**原页 §5 保留该问题**并注明 `→ [[新 gap 页]]`（不删）。

# 人工确认点汇总

一次也不该被 Agent 自动越过的动作：

| 确认点 | 在哪 | 为什么 |
|---|---|---|
