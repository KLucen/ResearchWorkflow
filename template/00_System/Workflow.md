# Workflow（操作手册）

> 本文件是**操作手册**：每个阶段做什么、产出什么、边界在哪。**纪律**以 `AGENTS.md` 为准，**路径与参数**以 `Config.md` 为准。
> 三个阶段：**ingest（引入）** · **query（问答）** · **lint（体检）**。

## 0. 一页总览

```text
Zotero（不可变源：PDF + 元数据 + 批注）
        │  只读；PDF 不进 Vault
        ▼
 ingest：只出一份 5 分钟导读
        └──► 01_Papers/pass1/待精读/<zotero_key>_<短标题>.md
        │
        ▼
 研究者带导读读原文 → 做五色批注（Zotero 里）
        │
   「读完了 / 批注好了」
        ▼
 生成 01_Papers/pass2/<同名>.md（13 节 + E 对象 + 1–3 问 + §11 提案）
 同时把导读移入 01_Papers/pass1/已精读/
        │
        ▼
 研究者回答 → R 对象 → 主张级提案 → 研究者批准 → 写入 02_Wiki/
        │
        ▼
      query / lint
```

**核心时序铁律**：**先导读、后成稿**。`pass2/` 的证据基础是「研究者批注 + Agent 通读」；**缺批注就不生成**——否则会产出一个未经确认、却长得像结论的证据源。

**位置即状态**：导读在 `待精读/` = 尚未成稿；`pass2/` 存在则该导读应在 `已精读/`。**不在导读里写状态字段**（那是双写）。

## 1. ingest（引入一篇新论文）

**输入**：Zotero item key（或条目链接）；可选：集合 / 标签。
**触发**：研究者说「读这篇 / ingest 这篇 `<key>` / 把这个条目引入」。

### 阶段 1-A：检索与通读

| # | 动作 | 要点 |
|---|---|---|
| 1 | 读 Zotero 元数据 | `search` 定位 → `get` 取元数据 + 笔记 |
| 2 | **取研究者批注** | `annotations`；**并查清批注挂在哪个附件上**，有无分页截断（见 `Zotero_Access.md` §4） |
| 3 | 取 PDF 全文 | `attachment` 取路径 → 提取文本；Zotero 全文索引（`retrieve`）可作交叉核对 |
| 4 | 理清论文**自身的章节编号与页码** | 只到"章"这一层；**不逐小节**；页码基准写明是**哪个附件** |

> 若某条目的元数据有明显缺口（缺 authors / year / venue / DOI），照实记下，在导读与笔记中标注**缺失**——**不要猜**。

### 阶段 1-B：写 5 分钟导读

**产出**：`01_Papers/pass1/待精读/<zotero_key>_<短标题>.md`（`pass1/_Reading_Guide_Template.md`，`schema_version: 4`）

固定七段：

| 段 | 内容 | 约束 |
|---|---|---|
| 顶部 | 页码基准（哪个附件）+ 一句话 | ≤ 40 字，**不评价** |
| 一、要解决的问题 | Problem / Gap / Motivation | ≤ 150 字；**不写它做成了没有** |
| 二、论文架构地图 | `章 \| 页 \| 在做什么 \| ★ \| 建议` | 一行一章；★ 按"与研究者的研究相关、可复用"评，**不按作者篇幅权重** |
| 三、核心观点 | 作者**明确声称**的贡献与主张 3–5 条 | 每条标章节定位；**不写实验数字与最终结论** |
| 四、读前必备的概念与记号 | 3–5 条 | 只给"是什么" |
| 五、阅读路线 | `目的 \| 读法 \| 约需` | 给几条可选读法 |
| 六、带着这几个问题读 | 3–5 问 | 每问附**一行定位**；判断类标「**论文不答**」 |

**边界铁律（缺一即违规）**：

- **全文 ≈ 1000 字，1200–1300 中文字为上限**（宁短不长）。
- **不逐小节展开**（小节信息只出现在架构地图的"在做什么"格里）。
- **不复制论文的标题层级结构**，但保留章节编号以便对照原文。
- **不写实验结果、数字、作者对结果的解释与最终结论**——「核心观点」只记录作者**声称**什么，不记录作者**证明了**什么。
- 论文无清晰章节时，退化为「摘要 / 引言 / 方法 / 实验 / 讨论 / 附录」粗分块并注明。
- **不写** `E` 对象、主张、Wiki 提案、`R` 对象、`PENDING_RESEARCHER_RESPONSE`。
- 写之前**单独扫一遍无编号的尾部小节**（`Limitations` / `Ethics Statement` / `Broader Impact` 之类）：编号标题扫描**抓不到**它们，漏扫会得出「本文没有 Limitations」这种错误结论。

### 阶段 1-C：收尾

**本轮到此为止**：`log.md` 追加一行。**不写 `pass2/`**（等批注）。告知研究者：「导读已生成，请读原文并做五色批注，完成后说『批注好了』。」

## 2. 生成精读总结（`pass2/`）

**触发**：研究者说「**读完了**」/「**批注好了**」，或在对话中继续追问。
**输入**：该论文的 Zotero 批注（五色）+ 已有导读 + Agent 通读。
**产出**：`01_Papers/pass2/<同名>.md`（`pass2/_Paper_Template.md`）；导读移入 `pass1/已精读/`。

| # | 步骤 | 要点 |
|---|---|---|
| 1 | **先读批注，再读原文** | 按五色分流（下表）；批注**优先于** Agent 通读结论 |
| 2 | **批注沉淀** | 转成 `E` 对象（`source: annotation:<颜色>`），写入 **§8 批注沉淀**；§8.1 研究者评论 / §8.2 机器词典 / §8.3 Agent 补充 |
| 3 | **写 §1–§7** | 以通读为底；**受批注影响的段落用 `==高亮==` 包住** |
| 4 | **提 1–3 个问题** | 写入 `R` 对象；未答的填 `PENDING_RESEARCHER_RESPONSE`（**不得代答**） |
| 5 | **Agent 补充** | 批注很少时可补重点，但**必须标注为 Agent 补充**（§8.3），不得混入研究者信号 |
| 6 | **主张影响检查** | 本次证据是否触及 `02_Wiki/` 已有主张？更新 **§11 主张级变更表** |
| 7 | **请求批准** | 会改动实质研究论断的 Wiki 变更，先请示再写 |
| 8 | **收尾** | `reading_status: deep-read`；导读移入 `已精读/`；批准并写入 Wiki 后置 `completed`；`log.md` 追加一行 |

### 五色批注分流执行口径

| 颜色 | 语义 | Agent 动作 | 落点 |
|---|---|---|---|
| 🟡 `#ffd400` | 生词 | 归入词元（lemma） | `03_Vocabulary/<lemma>.md`（追加一节；**不进** E 对象 / Wiki） |
| 🟢 `#5fb236` | 定义术语或术语解释 | 建 `E` 对象 | `pass2/` §4 + §8；有独立价值时 → `02_Wiki/concept/` |
| 🔵 `#2ea8e5` | 影响、观点、解决方法 | 建 `E` 对象（默认 `+`） | `pass2/` + §11 提案 → 主张登记表 |
| 🔴 `#ff6666` | 缺陷、现有问题、现有挑战 | 建 `E` 对象（`−`） | `pass2/` §6/§8 → §11 提案 → 分歧、`gap/`（主要来源） |
| 🟣 `#a28ae5` | 与我的研究相关 | 不建证据对象，进研究关系 | `pass2/` §7；作为 `research_position` / `research_relevance` 的**首要依据** |

**评论归属**：每条的 `annotationComment` 一律**按 `🔤…🔤` 区间切分**——区间内 = 机器词典（`tool_generated`）；区间外非空文字 = 研究者本人的话（记入 §8.1）。**不得因整条含 `🔤` 就整条丢弃。**

**条数上限提醒**：读批注时用自动分页的 `annotations` 子命令；若直接调用底层接口，**批注会在 100 条处静默截断**（不报错）。判据与补齐办法见 `Zotero_Access.md` §4.2。

### 提问清单（一次最多 1–3 个）

优先问那些**会实质改变解读或研究相关性**的问题：

- 「作者声称 X。你认为这个结论可信吗？为什么？」
- 「哪个贡献对你的研究最重要？」
- 「你认为这个方法能迁移到你的研究情境吗？」
- 「哪个局限会让你无法采用这个方法？」
- 「这篇论文是否应该改变 Wiki 中关于 X 的现有理解？」

**不得编造回答。** 未答处保留 `PENDING_RESEARCHER_RESPONSE`，下次从第一个未答块继续。

### 两种标记

- `==高亮==` = **这段来自批注**（让"批注带出来的"一眼可辨）。
- 行末 `（Pass 2 补充）` = **这一处是后来补进去的**（研究者继续批注或回答问题时用）。

## 3. query（研究问答）

**触发**：研究者问「文献里关于 X 的证据 / 观点 / 方法」「这个结论出自哪里」「跨论文综合一下」。

### 顺序（不得跳步）

1. **先 `02_Wiki/`**：找 `topic/` / `concept/` / `synthesis/` / `gap/` / `entity/` 里的相关页与主张行（`§2` 表）。
   - 检索期**默认过滤 `retired_at` 非空的内容**；被问起时标注「此条已废止」。
2. **不足时下钻 `01_Papers/pass2/`**：顺证据列的三件套 `[[Paper Note]]E编号 (页码)` 点回原文位置，核对该 `E` 对象的 `quote` / `location` / `confidence`。
3. **仍不足时读 Zotero**：用 `retrieve`（全文索引排序片段）/ `fulltext` / `attachment` + 文本提取，取原始证据（**注意 `truncated` 与 `sourcesSkipped` 信号**）。
4. **按四分类作答**（见下），并给出来源位置；**`pass1/` 是导读，不作为引用来源。**

### 回答必须四分类

| 分类 | 含义 |
|---|---|
| **established evidence** | 已确立的证据（独立来源充分、无 `−` 证据） |
| **conflicting evidence** | 彼此冲突的证据（说明各自适用场景：时间 / 对象 / 领域 / 任务） |
| **researcher-approved interpretation** | 研究者已批准的解读（注明批准时间与出处） |
| **unresolved uncertainty** | 未解决的疑点（说清缺什么证据） |

**不得**把 Agent 推断混入前两类；**不得**把未批准的研究者判断当已批准。

### 回答后（可选但推荐）

若问答产生了新知识：走**主张级提案**（§11 表格 → 研究者批准 → 写入 `02_Wiki/`），不要让结论只活在对话里。

## 4. lint（体检）

**触发**：研究者说「lint / 跑一次体检」，或每第 5 篇 ingest 后 Agent **建议**执行。
**产出**：**覆盖写** `00_System/lint-report.md`（唯一输出位置）+ 对话内给摘要与修复建议 + `log.md` 追加一行。

### 六组检查

| 组 | 检查项 |
|---|---|
| **Structure（结构）** | YAML 非法/缺失 · 断链 · 必填字段缺失 · **导读位置与 `pass2/` 是否一致**（`待精读/` 应无 `pass2/`；有 `pass2/` 的导读应在 `已精读/`；导读落在 `pass1/` 根下即违规）· **导读体量 ≤ ~1300 中文字** · **pass1 双写违规**（出现 `E` 编号 / 主张 / Wiki 提案 / `R` 对象 / `PENDING_...`；顶部"本文不含 E 对象"这类**免责声明行不算违规**）· Wiki 内容页是否落在五个类型目录之一 · frontmatter 是否残留 `type` · 主张证据列**三件套完整性** · 页尾追加痕迹 · `_WikiIndex.md` 与各页正文是否一致 · Vocabulary 词条（文件名 ↔ `lemma`、`encounters` 条数、`acquired` 是否被 Agent 自标）· Paper Note 章号与模板 |
| **Evidence（证据）** | 论断无引用 · 引语无位置（page/section/figure/table） · 综合无证据支撑 |
| **Provenance（溯源）** | 未经批准的研究者判断被写入 Wiki · Agent Interpretation 被误标为研究者判断 |
| **Knowledge（知识）** | 重复的 Wiki 概念 · 陈旧页面（`last_reviewed` 超期） · 未记录的矛盾 · 该更新而未更新的 Wiki 页 |
| **Claims（主张一致性）** | 标 `consensus` 但独立来源 < 2 篇（或标 `supported` 但仅 1 篇）· 标 `contested` 却无任何 `−` 证据 · 证据列的 `E` 编号在对应 Paper Note 中不存在（悬空）· 同一主张在多个页面重复登记 · §2 出现整行删除痕迹而无 §6 变更记录 |
| **Research（研究）** | 反复出现的未决问题 · 证据缺口 · 跨论文新兴主题 · 可能的研究空白 |

**两条判据口径（避免误报）**：

- **`E` 编号唯一性**只在 **Paper Note 的 §4 关键证据表**内检查。§8.1 按颜色列出的批注表会**复述同一个 `E` 编号**（批注记录与证据登记是两张表），**不算重复**；§4 的行数 = `E` 编号的最大值即连续无跳号。
- **pass1 免责声明行不算违规**：判违规的是**真的写出了** `E01` 这样的编号、`PENDING_...` 字面量或提案表。

### 定期检查四类（每第 5 篇 ingest 后**建议**执行）

> 前三类涉及批量核查时**必须输出覆盖清单**——**没有覆盖清单的核查不算完成，且要全量、不抽样**。

| 类 | 做什么 |
|---|---|
| **A. 去重合并** | 按 `topics` 聚类，找语义重复 / 已被取代 / 过度碎片化的条目；合并时旧页标 `retired_at` + `superseded_by`（**不删**）；重建 `_WikiIndex.md` 与受影响页的 §1 |
| **B. 回原始核查** | 逐段对照 `pass2/` 的 `E` 对象：**漏了关键限定**（如"仅在英文中"被省略）· **丢了否定词**（"不推出"写成"推出"）· **丢了时间条件**（"2016–2020 美国"被省略）· **把推测当事实**（Provisional 解读被写成结论） |
| **C. 冲突场景限定** | 矛盾的两条若**各自成立**：是否写明适用条件（时间 / 对象 / 领域 / 任务）；证据不足的是否**保留待确认**（未强行裁定） |
| **D. 失效下线** | 过期内容已加 `retired_at` 且检索期被过滤；被问起时摘要中标注「此条已废止（失效于 …，由 `Cxx` 取代）」 |

**Agent 的边界**：可以**建议**跑合并检查、可以执行；但**不得自行**把 exploration 升为核心、不得删除任何 Zotero 条目、不得删除 Wiki 行。

### `lint-report.md` 的结构（覆盖写，保持稳定）

标题 + 覆盖写说明 + 生成时间行 → 六组勾选清单（带历史遗留例外与免责说明）→ `---` → 定期检查四类 → `---` → **覆盖清单（批量核查必填）**：

```markdown
| # | 对象（页 / 主张） | 检查项 | 结论 |
|---|---|---|---|
| 1 |  |  |  |
```

末尾一行「本次覆盖：`_ / __` 页，`__ / __` 条主张」。

## 5. 交互规则

- 精读时保持简洁、苏格拉底式：**证据先行，然后一个问题**；不要输出长篇泛泛评论。
- **一次精读会话最多问 1–3 个**高价值问题。
- 从第一个未回答的 `PENDING_RESEARCHER_RESPONSE` 块继续。
- 需要研究者决策时给**带推荐项的选项**，而不是开放式问题。

## 6. 执行细节

| 场景 | 做法 |
|---|---|
| 读原文 | ① Zotero 全文索引（`retrieve` / `fulltext`）默认路径；② 兜底：`attachment` 取 PDF 路径 → 文本提取到**系统临时目录**（**不进 Vault**）；③ 批注 / 笔记 + 摘要（信息不足时用，须标注来源层级） |
| 读批注 | `annotations` 子命令（自动分页）；按颜色分流 + 评论按 `🔤…🔤` 区间切分；先确认批注在哪个附件上（`Zotero_Access.md` §4） |
| 提问落地 | `R` 对象写入 `pass2/` §8/§10；未答置 `PENDING_RESEARCHER_RESPONSE` |
| Wiki 变更闸门 | **先提案（§11）→ 研究者批准 → 才写入 `02_Wiki/`**；写入走最小 diff，禁止页尾追加 |
| lint 输出 | 覆盖写 `00_System/lint-report.md`；无覆盖清单的批量核查视为未完成 |
| 日志 | `log.md` **只追加**一行（日期 / 动作 / 对象 / 结果 / 备注），不重写历史行 |
| 换机器 | 先填 `Config.md` 的环境事实表，再跑 `python tools/zotero/rvzotero.py ping` 自检 |
