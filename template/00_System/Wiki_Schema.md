# Wiki Schema（schema v4）

> Wiki 不是论文摘要的堆放处，而是**可进化的跨论文知识层**：每次精读都在已有主张上做增量修改，而不是新建一页重新开始。
> **目录即类型**：页面放在哪个目录就是哪一类，**frontmatter 不写类型字段**。
>
> 执行纪律见 `AGENTS.md`；Paper Note 侧结构见 `Paper_Schema.md`。

---

## 1. 五类页面（目录即类型）

| 目录 | 回答的问题 | 核心产物 | 证据取向 |
|---|---|---|---|
| `topic/` | 「这个方向由哪些问题构成？」 | **方向地图**（本身不写主张） | 指向 concept / synthesis / gap |
| `concept/` | 「X 是什么？」 | **working definition** | 各论文对 X 的定义、用法、边界 |
| `synthesis/` | 「关于 X，文献整体说了什么？」 | 带边界的**当前最佳理解** | 各论文的实证 / 机制 / 效果主张 |
| `gap/` | 「什么还不知道、值得做？」 | **可研究问题 + 验证路径** | 各论文自述的局限 / future work / 未覆盖设定（🔴 红色批注是主要来源） |
| `entity/` | 「这个具体的人 / 组 / 系统 / 模型 / 数据集是谁？」 | 实体档案 | 跨论文反复出现的专名 |

**判据**（拿不准时按这个顺序问）：`topic` 最粗（一个研究方向）→ `concept` 有「定义」的对象 → `synthesis` 跨论文的主张 → `gap` 可研究的问题 → `entity` 专名。

**目录即类型的三条后果**（必须知道，否则会写出不合规的页）：

1. **frontmatter 不写类型字段**——移动文件就是改类型，不存在第二份真相。
2. **Dataview 查询用 `file.folder`**，不是类型字段。
3. `02_Wiki/` 根目录下**只允许放 `_` 前缀的基础设施文件**（`_WikiIndex.md`、`_Wiki_Template.md`）；**任何非 `_` 前缀的内容页都必须落在五个目录之一**，否则 lint 报错。

> 用不到的类别可以留空目录，但**不要临时新增第六个目录**——类型集合一改，所有历史查询与 lint 规则都要跟着改。确实需要新类型时，先改本文件与 lint 规则。

## 2. 进化链条（本框架的核心）

```text
多篇论文（Paper Note 中的 E 证据对象）
        │  每次精读挂载
        ▼
§2 主张登记表  ←── 唯一事实源：行只增、状态只改，行永不删除
        │
        ├──────────────► §3 共识（已达 consensus 的主张 + 适用边界）
        │
        └──────────────► §4 分歧（contested 的主张 + 分歧根源 + 适用条件）
        │
        ▼  研究者批准后
§1 综合与当前理解（本页最接近结论的部分）
        │
        ▼
§5 未解决问题 ──满足升级条件──► 新的 gap/ 页 ──► 引出新的 concept / synthesis
        │
        ▼
§6 变更记录（知识如何进化，可回溯）
        │
        ▼
_WikiIndex.md（投影：主题清单 / 最近变更 / 开放问题 / 验收指标）
```

**可进化的三个必要条件**（都已在骨架里落实）：

1. **主张有稳定 ID**（`C01, C02, …`）——否则无法追踪同一条主张的演变；
2. **行永不删除，只流转状态**——否则看不到「共识如何被推翻」；
3. **每次 ingest 必做主张影响检查（claim impact check）**——否则新证据进不来。

## 3. Frontmatter（元数据）

```yaml
---
schema_version: 4

title: ""
status: draft              # draft | active | retired
effective_from: 2026-01-01 # 本页结论开始生效
retired_at:                # 空 = 现行；非空 = 已下线
superseded_by:             # 被哪一页取代（空 = 无）

domains: []
topics: []                 # 所属主题 ← **批量合并的聚类键**

source_papers: []          # 贡献过证据的 Paper Note 文件名（不含 .md）

confidence: low            # low | medium | high
created: 2026-01-01
updated: 2026-01-01
last_reviewed: 2026-01-01
---
```

| 字段 | 说明 |
|---|---|
| `status` | `draft`（新建待复核）\| `active`（现行）\| `retired`（已下线，保留供回溯） |
| `effective_from` / `retired_at` | **能遗忘**的基础：`retired_at` 非空即已下线，**检索期默认过滤** |
| `superseded_by` | 被哪一页取代；仅 `retired` 时填 |
| `topics` | **批量合并的聚类键**。每页至少 1 个；合并检查按它分组 |
| `source_papers` | 供 Dataview 反查与断链检查 |
| `confidence` | 页面级置信度，反映**综合结论**整体可靠程度 |

**刻意没有的字段**：

- **类型字段**——由目录推导（见 §1）。
- **`claim_count` / `contested_count` 等计数**——它们**可以从 §2 表算出来**，写进 frontmatter 就是状态双写。这类验收指标统一放在 `_WikiIndex.md` 的验收区，由检查生成。

## 4. 正文六节

### §1 Synthesis / 综合与当前理解

- 3–6 句，写本页**最接近结论**的东西。
- 只允许写：已达 `consensus` 的主张、研究者明确批准的判断。
- 写清**适用边界**（在什么设定下成立、在什么设定下未知）。
- 每次实质更新**重写本节**——这是全页唯一允许整段重写的地方。

### §2 Claim Registry / 主张登记表 —— 唯一事实源

| ID | 主张 | 证据 | 状态 | 批准 | 生效 | 失效 | 替代 |
|---|---|---|---|---|---|---|---|
| C01 | 示例主张：在某设定下 X 与 Y 正相关 | +[[Paper Title]]E03 (p.5) · −[[Another Paper]]E07 (p.9) | contested | — | 2026-01-01 | — | — |

**证据列写法（检索命中依据的关键）**：`+` 支持 · `−` 反对 · `~` 限定（仅部分成立 / 仅在特定设定下成立）。
每条证据**必须**是 `[[Paper Note 文件名]]E编号 (页码)` 三件套：

- `[[…]]` **可点击**——从 Wiki 命中直接跳回 `pass2/` 笔记；
- `E编号` 指到笔记 §4 的具体证据行；
- `(页码)` 让你不必在笔记里翻找。

**没有回链的主张视为无依据**，lint 报警。

**列含义**（这张表同时回答「能吸收 / 能纠错 / 能遗忘 / 能验收」四问）：

| 列 | 回答的问题 |
|---|---|
| `主张` | 这条论断是什么 |
| `证据` | **从哪条证据而来**（论文 + E 编号 + 页码） |
| `批准` | **谁在什么时候批准**（`研究者 · 2026-01-01`；`—` = 未经批准） |
| `状态` | 证据强度处于哪个档位 |
| `生效` / `失效` | 起止日期。**失效非空即已下线，检索期默认过滤** |
| `替代` | 被哪条主张取代（`→ C07`） |

**三条铁律**：

1. **行永不删除**——推翻是正常的知识进化，不是要抹掉的错误。
2. 状态只能按 §5 的流转表变更，**不能跳级**。
3. ID 页内唯一、**永不复用**。

### §3 Consensus / 共识

**只写解释，不重复列主张**（用 `C` 编号引用）。要写的是：

- 这条共识的**适用边界**（在哪些模型 / 数据 / 任务 / 语言上成立）；
- 它**为什么可靠**（独立重复了几次、是否跨研究组）；
- 写入 §1 的哪一句。

### §4 Disagreements / 分歧

每条分歧必须写全四件事：

1. 对立双方的主张编号（如 `C02` vs `C07`）；
2. **分歧的根源**——设定不同、数据不同、定义不同，还是评测方法不同（多数分歧源于此，而不是有人错了）；
3. **适用条件**——若两条主张**各自成立**，必须写明各自成立的时间 / 对象 / 地域 / 任务；**证据不足以判定适用条件时，保留待确认状态**，不要强行合并；
4. 目前的判断：未决 / 倾向哪一方 / 需要什么证据才能裁定。

### §5 Open Questions / 未解决问题

每条问题写两件事：

1. 问题本身；
2. **还缺什么证据**才能回答它。

并标注是否已够格升级为 `gap/` 页（见 §6）。

> `gap/` 类型页面的例外：本节是**页面主体**，每条写成 —— **RQ** / 为什么重要 / 需要什么证据 / 可行性（数据 · 算力 · 时间）。

### §6 Change Log / 变更记录

一行一次变更，格式：`日期 — 变更类型 — C 编号 — 触发来源`。

变更类型固定为：`新增主张` / `状态流转` / `新增分歧` / `分歧消解` / `共识达成` / `升级为 gap` / `页面创建` / `页面退役`。

> 这一节是「可进化」的可见证据：读它就能知道这个页面的理解是怎么一步步变过来的。

## 5. 状态流转表

| 从 | 到 | 触发条件 |
|---|---|---|
| `proposed` | `supported` | 第 2 篇**独立**论文给出 `+` 证据 |
| `supported` | `consensus` | 研究者明确批准（Paper Note 中 `approved_for_wiki: true` 的 `R` 对象） |
| `supported` / `consensus` | `contested` | 出现 `−` 证据，强度相当或更强 |
| `contested` | `consensus` | `−` 证据被限定解释（转为 `~`），或研究者裁定 |
| 任意状态 | `refuted` | 被明确推翻 |

**独立性的定义**：不同研究组、或在不同数据集上的独立验证。**同一篇论文的多个实验不算独立**；综述对被转述论文的转述也**不算**第二个独立来源。

**双向流转**：`contested → consensus` 与 `consensus → contested` 同样重要。共识被推翻不是事故，是本框架正常工作的表现——只要 §6 记录在案。

**状态 ≠ 是否现行**：状态说的是**证据强度**，`失效` 说的是**是否仍是当前答案**。一条 `supported` 的主张完全可能因为被更精确的主张取代而失效（此时填 `失效` + `替代`，状态保持不变）。

## 6. gap 升级条件

未解决问题满足**任一**条件，Agent 应**建议**升级为独立 `gap/` 页（需研究者批准，**不得自行创建**）：

1. 在 **≥2 个** Wiki 页中重复出现；
2. 有明确的**缺失证据类型**（如：没有人在某语言、某设定、某规模下验证过 X）；
3. 研究者判断其重要。

升级时在**原页** §5 保留该问题并注明 `→ [[新 gap 页]]`（不删），同时在新页 §6 记录来源。

## 7. 提升规则（Promotion rule）

研究者的判断在获得**明确批准**之前，不得成为 Wiki 的持久论断。Agent 生成的解读可以作为暂定上下文存入，但**必须明确标注**，且不得呈现为研究者本人的观点。

**紫色批注不是批准**：它是「与我的研究相关」的标记，只能作为 `R` 对象的候选。

## 8. 语言与引文

- 正文一律用**中文**书写。
- 引用论文原文时**保持原语言并附中文翻译**；短句用 `"…"（译：…）`。
- 数字、单位、公式、变量名、模型名、数据集名、指标名**不译**。
- frontmatter 的**键与枚举值保持英文**（Dataview 与 lint 依赖它们）。

## 9. 文件与写入约定

- **文件名**：`02_Wiki/<目录>/<短标题>.md`（文件名创建后保持稳定；重命名会打断 `[[链接]]` 与 `source_papers`）。
- **来源引用**：`source_papers` 填 Paper Note 文件名（不含 `.md`）；正文用 `[[Paper Note]]` + `E` 编号 + 页码。
- **写入纪律**：小改动只补必要行与小节；**§2 表只增行或改状态，绝不删行**；每次改动在 §6 记一行。
- **模板**：`../02_Wiki/_Wiki_Template.md`（五类共用，按目录调整证据取向）。
- **入口页**：`../02_Wiki/_WikiIndex.md`。
- **frontmatter 不写类型字段**——再强调一次，这是本层最容易被误加的字段。

## 10. WikiIndex 规范（入口页）

`_WikiIndex.md` 是**投影，不是事实源**——与页面正文冲突时，以页面正文为准。四个区：

| 区 | 内容 | 谁维护 |
|---|---|---|
| §1 主题清单 | 按 `topics` 分组列出全部页面 + 五类目录导航 | **Dataview 自动** |
| §2 最近变更 | 按 `updated` 排序的页面列表 | **Dataview 自动** |
| §3 开放问题 | 各页 §5 与 gap 页 RQ 的当前未解决项；已升级的只留指针 | **Agent 增量重建** |
| §4 验收指标 | 页面数 / 主张数 / 状态分布 / 悬空引用 / 已退役 / 单来源占比 / 缺 `topics` | **Agent 每次检查后重建**（可自动统计的部分见页内查询块） |

**为什么不把计数写进每页 frontmatter**：那些数字从 §2 表算得出来，写两处就是双写。指标集中在入口页一处，才是单一事实源。

## 11. 检索链与命中依据

```text
提问
 └→ _WikiIndex        定位主题（§1 主题清单）
     └→ topic/        方向地图
         └→ concept/ + synthesis/ + gap/     §2 主张行
             └→ 证据列 `[[Paper]]E03 (p.5)`  ← 可点击
                 └→ pass2/ 笔记 §4 证据表     原文摘录 + 译文 + 精确位置
```

**命中依据的硬要求**：

1. Wiki 每行主张的证据列**必须**是 `[[Paper Note]]E编号 (页码)`——缺一不可（lint 查）。
2. 从 Wiki 层检索到的任何结论，都必须能在**两次点击内**到达论文原文位置。
3. **`retired_at` 非空的页面与 `失效` 非空的主张，检索期默认过滤**；只有研究者显式问「这条为什么变了 / 历史是什么」时才纳入，并在回答中标注「**此条已废止**（失效于 YYYY-MM-DD，由 `Cxx` 取代）」。

## 12. 更新纪律（最小 diff）

每次更新 Wiki，按这个顺序：

1. **先跑检查**：frontmatter 合法 / 链接可达 / 证据链完整（`E` 编号存在）/ 无失效引用；
2. **定位受影响的「具体行」**——不是整页；
3. **增删改对应段落**，并同步维护：链接 / `topics` / `updated` / 证据引用 / §6 变更记录；
4. **增量重建 WikiIndex 的受影响区**（§3、§4），不要整页重写。

> **禁止把新素材粗暴追加到页尾。** 这是最容易被违反、也最破坏可读性的做法——它会让页面退化成时间线，而不是知识页。lint 会检查这一模式（信号：出现了未被 §6 覆盖的新主张行，或页尾堆着「补充：…」）。

## 13. 定期检查（四类）

| 检查 | 做法 | 产物 |
|---|---|---|
| **去重合并** | 按 `topics` 聚类 → 找语义重复 / 已被取代 / 过度碎片化的条目 → 删除或归并或重写；**归并时旧页标 `retired_at` + `superseded_by`，不删**；重建入口页与索引页 | 覆盖清单 |
| **回原始核查** | **逐段**对照 `pass2/` 的 `E` 证据对象，专项查四类腐化：**漏了关键限定 / 丢了否定词 / 丢了时间条件 / 把推测当事实** | 覆盖清单 |
| **冲突场景限定** | 矛盾的两条若**各自成立**，在 §4 写明适用条件（时间 / 对象 / 地域 / 任务）；**证据不足则保留待确认状态**，不强行裁定 | §4 |
| **失效下线** | 给内容加 `effective_from` / `retired_at`；检索期过滤，或在摘要里标注「此条已废止」 | 查询行为 |

**覆盖清单（coverage manifest）是硬要求**：大批量核查**必须**输出「检查了哪些页、哪些主张、每条的结论」，写入 `lint-report.md`——**保证全量而非抽样**。没有覆盖清单的核查不算完成。

**触发**：内容量增长到**每第 5 篇 ingest** 时，Agent 应**主动建议**跑一次合并检查（建议但不自行执行，等研究者点头）。
